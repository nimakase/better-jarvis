## 1. 基础收发 + JSON 2.0 迁移

- [ ] 在飞书给机器人发「你好」。
- [ ] 预期：先出「⏳ 正在思考...」占位卡，随后**打字机式**刷出回复；卡片头是
      「🤖 贾维斯」。日志有 `[飞书] 收到消息: 你好` 与 `[飞书] ✅ 已回复`。
- [ ] 富文本检查：让它回一段带 **加粗**、`代码`、列表的内容，确认 2.0 markdown 渲染正常。
- [ ] `/reset` → 出「✅ 会话已重置」，历史清空。

> 出错：卡片发不出且日志 `发送卡片失败 code=… msg=…` → 多半是权限/卡片能力没生效。

## 2. 卡片回调（按钮/表单点击）★ 本次重点

**按钮**
- [ ] 触发一次代码审查场景：让贾维斯改/建一个小工具（如「给我建个算平方的工具」），
      它会发一张代码卡。
- [ ] 说「用按钮让我确认」或直接让它 `send_choice_buttons`；预期出现一张带
      **【激活】/【修改】/【放弃】**之类按钮的卡。
- [ ] 点【激活】。预期：① 立刻弹 toast「已收到 ✅」；② 日志出现
      `[飞书] 卡片回调 → 意图: 激活 …`；③ 贾维斯像收到你打字一样执行激活并回复。
- [ ] 反例检查：点【放弃】应触发它对应的 intent（不激活），不应误激活。

**表单**
- [ ] 说「帮我新建个日历事件，用表单收」→ 预期出一张含**标题/时间/地点**输入框 +
      【提交】按钮的表单卡。
- [ ] 填几项点提交。预期：toast「已收到 ✅」；日志
      `[飞书] 卡片回调 → 意图: 新建日历事件（表单内容：title=…；when=…）`；
      贾维斯据填写内容继续动作。

> 出错：点了没反应、日志无「卡片回调」→ 后台卡片回调能力没开，或按钮 value 没带
> `__jarvis_intent__`（正常由工具自动带）。

## 3. 多模态接收（图片/文件/语音/富文本）

- [ ] **图片**：发一张图片给它。预期它回复里提到「已保存到本机」；
      本机 `DATA_DIR/lark_inbox/` 下出现 `时间戳_resource` 文件。
      （macOS：`~/Library/Application Support/Jarvis/lark_inbox/`）
- [ ] 顺带验业务：发一张**证件/银行卡**照片 → 它应提示可 `ingest_credential_image`
      本机识别（不外发）。
- [ ] **文件**：发个 xlsx/pdf → 回复提到文件名与本机路径；inbox 里能看到该文件。
- [ ] **富文本(post)**：发一段飞书富文本消息 → 它能读到其中文字（不再被丢弃）。
- [ ] **语音**：发条语音 → 回复提示「语音未转写；如需处理请告知」（当前不转写，符合预期）。

> 出错：日志 `资源下载失败 code=… msg=…` → 缺 `im:resource` 权限；
> `资源下载异常` → message_id/file_key 解析问题，把该条日志发我。

## 4. 让贾维斯「自己决定」用哪种形态

- [ ] 问一个**开放问题**（如「潜客名单怎么处理？」）→ 期望它在合适时**主动**用
      `send_choice_buttons` 给几个下一步按钮，而不是让你打字。
- [ ] 问一个**需要多字段**的需求（如「记一笔开销」）→ 期望它倾向用 `send_input_form`。
- [ ] 让它回一张**≥4 列的宽表** → 期望它改成**生成文件发送**而非贴表格。
- [ ] 普通闲聊 → 期望仍是纯文字，不会滥用按钮/表单。

> 这几条是「判断力」验证，不必 100% 命中；若明显偏保守（永远只回文字），
> 可微调 `core/channels.py` 的飞书画像措辞。

## 常见问题速查

| 现象 | 最可能原因 |
|---|---|
| 桥没起、无「长连接线程已启动」 | 凭据没填 / lark-oapi 没装 |
| 发卡失败 `code≠0` | 卡片能力或 im:message 权限未生效（需发布版本） |
| 点按钮无反应、无「卡片回调」日志 | 卡片回调能力没开 |
| 图片/文件下载失败 | 缺 im:resource 权限 |
| 原生流式建卡失败 | 缺 cardkit 权限；已自动降级，关开关即可 |
