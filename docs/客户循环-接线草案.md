## 一、OPEN vs PROTECTED 一览

| 要做的事 | 碰不碰 PROTECTED | 说明 |
|---|---|---|
| 新增连接器 `connectors/customer_loop_tools.py`(暴露工具) | **否(OPEN)** | `core/registry` 自动 import `connectors.*`;`@tool(effect=…)` 自带声明,不改 registry/effects |
| 注册夜间工作流(detach) | **否(OPEN)** | 走 `workflow_registry.register_workflow`,仿 `intel/workflow_defs` |
| 写外部动作过 effects/trust 两闸 | **否** | controller 分发前已自动拦;新工具标对 effect 即受管,**controller 零改动** |
| 建定时任务(每晚跑 nightly) | 否(但需你明示) | 用 jarvis 现有 scheduler / create_schedule |
| **回复路把 Breeze 标为 tainting** | **是(trust.py)** | 仅"回复路"阶段才需要(Breeze 读客户邮件=不可信);冷启动/分类器阶段**用不到**,故本期不动 |

**结论:本期接线(冷启动 + 夜间骨架)全部 OPEN,不需要动 PROTECTED。** 只有将来做回复路时,才有一处 trust.py 的 PROTECTED 改动,单独再审。

```python
"""

from core import effects
from core.registry import tool as _tool

    return os.environ.get("JARVIS_GRADE_VIEW_URL", "")

# 会话获取(仿 prospect_daily 的 hubspot_session),此处仅示意签名与 effect。

@tool("customer_loop_plan",
      "读全书账户、分级对账,产出【对账计划】(不写任何数据)。返回五桶计数+计划文件路径。",
      {"type": "object", "properties": {}},
      effect=effects.WRITE_LOCAL)   # 读外部 + 落本地计划文件
async def customer_loop_plan() -> str:
    # browser = 取已登录会话; 见下「会话」一节
    ...

@tool("customer_loop_apply",
      "【真写】把冷启动对账的【自动集】写回 HubSpot(fill_blank/priority_mismatch/type_promote)。"
      "manual_demote/skip_dead 不写。可选 limit 小批。",
      {"type": "object", "properties": {"limit": {"type": "integer"}}},
      effect=effects.WRITE_EXTERNAL)   # ★ 改外部系统,必须 write_external
async def customer_loop_apply(limit: int = None) -> str:
    ...
```

**要点**:`customer_loop_apply` 标 `write_external` —— 这正是「不能乱标 output」那条的落实:漏标会默认 `write_local`、偷跳两闸。
