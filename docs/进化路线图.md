# 贾维斯进化路线图

> 从「一个很靠谱的工具」到「在你划定的边界里，持续了解你、会自己变聪明、偶尔先你一步的助手」。
>
> 本文由三轮讨论收敛而成，按**依赖关系**与**价值/风险比**排优先级。核心原则贯穿始终：
> **能力可以无限长，能自己拍板的那条线始终是人划的。** 每扩一层感官/执行，先补一层运行时护栏。

---

## 零、当前架构的三个结构性判断

1. **有「结构自省」，没有「能力自省」。** `list_self_modules` 给的是文件地图；造工具时真正要问的是「这件事我已经能做了吗」。能力清单散在 `registry` / `skills/*/meta.json` / `workflow_registry` / `reports` 四处，没有统一入口——这是重复造轮子的根因。
2. **有「代码维度」的护栏，没有「运行时维度」的护栏。** `self_model`（哪个文件能改）+ `skill_policy`（技能能 import 什么）都是**静态、编译期**的。感知与执行扩张带来的风险是**运行时**的：这次动作有什么后果、这段数据可不可信。这两个概念现在完全不存在。
3. **有「边界」，没有「目标」；有「自我修改」，没有「监督信号」。** 主动性 = 目标 − 现状，两者都缺，所以只能被动响应。`self_review` 是闭卷冥想（读源码猜缺陷），因为运行遥测与你的反馈这两条燃料管都没接。

---

## 一、总体形态

| | 今天 | 更好的贾维斯 |
|---|---|---|
| 结构 | 一根主线程，独自从头干到尾 | 薄主线程 + 感官层 + 子 agent 群 + 会自整理的记忆 |
| 主线程职责 | 全部 | 只做三件事：对话、路由、裁决高风险动作 |
| 感知 | 你说话才醒 | 持续采样设备/邮箱/日程 → 世界状态总线 |
| 记忆写入 | 对话中在线判断「值不值得记」 | 离线巩固：短期全进，晚上复盘升华/修正/淡忘 |
| 长期规则 | 硬 prompt 手写 | L3 学习层，带 provenance，可增删改 |
| 护栏 | 代码维度（改哪个文件） | + 运行时维度（动作效应 + 数据信任） |

## 二、四个阶段（含依赖图）

```
阶段 0 地基（护栏 + 索引）      阶段 1 减负（子 agent）
  ├─ ① 能力索引 capability.py         ├─ ⑦ spawn 抽象
  ├─ ② 先查后建闸  ──依赖①            ├─ ⑧ 子 agent 工具白名单 ──依赖③
  ├─ ③ 动作效应 effects.py            └─ ⑨ 预算与强制交回
  └─ ④ 数据信任 trust.py ──依赖③
                                    阶段 2 感官（主动性地基）
阶段 3 记忆与学习                     ├─ ⑩ 设备/环境状态 sensors/ ──依赖④
  ├─ ⑬ 监督信号打标                   ├─ ⑪ 邮箱只读接入 ──依赖④⑩
  ├─ ⑭ 巩固作业 consolidation ──⑦⑬   ├─ ⑫ 浏览器 CDP 升级
  ├─ ⑮ profile 覆写/时效/provenance   └─ (桌面控制：最后做，价值密度最低)
  ├─ ⑯ episodic 衰减
  └─ ⑰ L3 学习层 ──依赖⑭⑮
                                    横切 ⑱ 执行遥测 ⑲ 能力回归集 ⑳ 目标层
```

依赖关键路径：**③④（护栏）先于一切执行扩张**；**⑦（spawn）先于 ⑭（巩固）**；**⑬（监督信号）越早开始攒数据越好**。

## 阶段 0 · 地基：护栏与索引（最高杠杆，成本最低）

先做这四个，它们是后面所有扩张的地基。顺序搞反，每接一个新感官都是裸奔着扩大攻击面。

### ① 能力索引 `core/capability.py`
聚合 registry tools + skills + workflows + reports + schedules 成统一清单，用已有的 `core/embedding.py` 建向量索引。暴露 `search_capability(intent)` 工具。
**一石三鸟**：造工具前去重、渐进披露选组依据、回答「你能干什么」不再靠背 prompt。

### ② 先查后建闸（依赖 ①）
在 `create_tool` 入口强制走一遍 ①：命中高相似度能力 → 返回「已有 X，建议 `edit_tool` 扩展 / 直接组合调用」，要新建必须显式说明差异。
优先级：**复用 > 扩展 > 组合 > 新建**。造工具是最后手段。与 `self_review` 的 necessity gate 同一思路——**默认拒绝，举证才放行**。

### ③ 动作效应模型 `core/effects.py`
给 `ToolSpec` 加 `effect` 字段（已有 `group`/`origin` 先例，改动小）：
```
read_local → read_external → write_local → write_external → irreversible
```
每个工具声明等级。controller 分发前查表，不同等级走不同闸门（直接执行 / 告知 / 需确认 / 需二次确认+冷静期）。现在这套逻辑散在 system prompt 的自然语言里（模型可忽略），落到代码里就不能。

### ④ 数据信任分级 `core/trust.py`（依赖 ③）
工具返回值标注来源可信度：网页正文、邮件内容、外部文档 = `untrusted`。硬规则：
> **本轮上下文里只要出现过 untrusted 数据，本轮就禁止调用 `write_external` 及以上的工具。**

要发邮件？先在干净上下文里重新起一轮。这条机械规则挡掉的 lethal trifecta 攻击面，比任何 prompt 叮嘱都多。**③④ 合计约两三百行，是地基中的地基。**

## 阶段 1 · 减负：子 agent（释放主线程）

> 子 agent 的价值 90% 来自**上下文隔离**，不是并行。一个子 agent 烧 40 轮只交回 300 字结论，主线程的上下文预算被保护——比省的时间值钱。现有 `BACKGROUND_BLOCKED_TOOLS` 那套非交互 controller 就是雏形，缺的是正规化。

### ⑦ `spawn(task, tools, budget) → 结构化结果`
返回值必须**契约化**（结论 / 证据链 / 不确定项 / 未完成部分），不是 transcript——否则主线程还得再读一遍原始过程，隔离白做。落盘到已有的 `workspace/results/`。

### ⑧ 子 agent 工具白名单授权（依赖 ③）
`BACKGROUND_BLOCKED_TOOLS` 是**黑名单**——方向错了（新增工具默认有权限，与 fail-safe 哲学相反）。改成**白名单**：子 agent 默认只拿 `read_local` + `read_external`，更高权限必须显式授予。

### ⑨ 预算与强制交回
轮次/时长/token 三个上限，超了交回**部分结果**而非失败。复用 controller 已有的 `_MAX_TOOL_ROUNDS` + 卡循环检测。

### 主线程变薄的目标
下沉给子 agent：造工具整条链路（`_gather_clarifications`/`_gather_env_probe`/`_gather_references`/codegen 循环——已是隐式子 agent，只缺统一抽象）、`self_review` 反思、记忆巩固、情报/潜客扇出调研（这类才是真正值得并行的形态）、长文档阅读。**主线程只留：对话、路由、裁决。**

## 阶段 2 · 感官：主动性的物质基础

> 现有 `connectors/` 全是「手」（被调用才动）。感知需要「眼」（持续采样）。建 `sensors/` + `core/world_state.py`（世界状态总线）。`scheduler` 只能定时跑固定任务，做不到「看到什么就做什么」。

### ⑩ 设备/环境状态 `sensors/`（依赖 ④，最便宜先做）
电量、网络、当前活跃应用、日程冲突、你在不在电脑前。纯只读、零风险，投入产出比最高。是「他知道现在该不该打扰你」的前提。

### ⑪ 邮箱接入（价值最高，严格三档推进，依赖 ④⑩）
一接上，lethal trifecta 就齐了（私密数据 + 不可信内容 + 对外通信）。`vault.py` 防的是云端泄露，防不住「贾维斯自己被邮件里的指令说服」。因此**必须先有 ④**。任务级工具授权：
1. **只读 + 摘要**（摘要任务只给读工具）
2. **起草进草稿箱**（给读 + 写草稿）
3. **发送**——永远需要你点头，`send` 永不授予自主权

别图省事跳过第二档。

### ⑫ 浏览器 CDP 升级
`env_probe` 已在驱动浏览器。往上走**优先 CDP/DOM 而非像素点击**（快一个量级、可判定、可写测试）。像素级 GUI 留给真没有 DOM 的场景。按风险选形态：调研走远程沙箱（隔离好），需登录态走本地控制（能力强）。

### 桌面控制（最后做）
价值密度最低——大部分「桌面任务」背后有 API/CLI，绕过 GUI 更稳。「能自己打游戏」那类 demo 对贾维斯实用价值低（游戏容错高、可重试、无副作用，与「操作网银」相反）。**值得抄的是工程手法不是能力本身**：可回放动作轨迹（每步截图+决策，事后复盘为什么做错）、沙箱先跑再上真实环境。前者可直接喂自我迭代闭环，是比读源码好得多的进化燃料。

## 阶段 2.5 · 自我处境感知（`world_state` 的「向内」子空间）

> 前面阶段 2 全是**对外的感官**（设备、邮箱、网络）。这一节是**对内的感官**——他对「我是谁、我状态如何、我跟你的关系怎样、我手里有什么」的感知。
>
> **判断依据**：一个 agent 从「工具」变「助手」，缺的往往不是更多对外能力，而是这层向内看的能力。「自制前端 vs 飞书」就是这层里第一个冒头的问题。
>
> 现状诊断：传输层客观上已按渠道分好了（`results.py` 的 `ToolResult(text, actions)` 渠道无关，`web/chat.py` 与 `lark_bridge.py` 各自落地同一套 action，`delivery.py` 按渠道路由）——**但 controller 拿不到「我这轮从哪个渠道来」**。渠道差异憋在传输层，大脑不知情，只有 system prompt 几句硬编码先验。补法统一：把这些做成 `world_state` 里的「自我处境」子空间，顺着 `context` 上报给大脑。

按性质分两类。

> ㉑ 发起人身份核验：**已删（2026-07-22，Ned 决策）**——访问贾维斯的物理/账号安全由 Ned 自行控制，不在贾维斯内部做人的身份核验。

### 🔴 处境感知

**㉒ 渠道感知驱动表达与 effect（改动最小）**
每轮请求把 `channel`（能力画像：富文本/表格/内联图片支持、文件大小上限、是否流式、是否交互）塞进 `context`。让他能：飞书上自动把宽表落成文件而非硬贴、网页放心用富卡片、后台定时任务里绝不问「要不要我帮你…」。渠道进 context 后，同时成为 ④ trust 的一个输入。

### 🟠 可靠性（决定他靠不靠得住）

**㉓ 自体健康感知 `sensors/health.py`（优先，放权前置）**
现在无任何自体健康感知：定时任务静默失败、connector 报错、HubSpot session 掉、证件过期没人提醒——他自己察觉不到。心跳 + 上次成功/失败 + 凭据到期倒计时进 world_state。是 ⑱ 遥测的延伸：**遥测=「我做过什么」，健康=「我现在还行不行」**。

**㉔ 动作回执 / 闭环**
`delivery.py` 多为发射即忘。邮件真发出了吗？飞书那头真收到了吗？交换机那个口真起来了吗？给高 effect 动作配「回执/核实」步骤——接了邮箱和弱电之后，「我以为我做了」和「真的做了」差别很大。

**㉕ 双向自我变更史（自改 + 外部改 + 漂移感知 + 和解闸）**

> **隐含假设被戳破**：整个自我模型默认「贾维斯是唯一改动自己的人」。但现实里你、外部工具（Cowork/Claude 等）、git、别的编辑器都会从旁边改他，而他的世界观里没有「外部」这个概念。这不是理论担忧，现在就有两个具体的洞。

**洞一：自我认知会悄悄过期。** `self_review` 的冷却判断靠 `_recently_applied()`——它读的是**自己写的复盘文档**（`docs/self_review/*.md`），不是真实 git 历史。你昨天让外部工具改了 `core/calendar.py`，他完全不知道，下一轮可能对着你刚调过的文件重新提改动。㉕ 若只记自改，记的是一本**残缺自传**。

**洞二（更危险）：自我迭代可能冲掉外部改动。** `self_iteration.py` 的安全靠「改前快照 → 出错回滚」，快照的是**执行那一刻**的内容。若那一刻有未提交的外部改动，回滚会把它一起抹了，git commit 也可能把两者混进一条提交。**护栏是为「只有他自己动」设计的，遇到并发外部手会误伤。**

**病根**：他把文件系统当「我说了算的私有状态」，而它其实是「随时被别人改的共享状态」。

**解法：让 git 成为「我身上发生过什么」的事实源**（工具已在手边，他自己就在 commit，只是只写不读）：
1. **漂移感知（sensor）**：启动时 + 定期，把 `HEAD`/工作树跟「上次我记得的状态」对比，发现外部提交/改动 → 归因（自改/外部工具/人手）写进变更史，并**主动告诉你**「我注意到 X 被改过，不是我改的」——「向内的感官」该有的样子。
2. **和解闸（reconciliation gate）**：自我迭代开跑前**先查工作树干不干净**，有未提交外部改动 → 这轮不碰那些文件（甚至整轮暂停），绝不拿旧快照覆盖。冷却判断从「读自己复盘」升级为「读真实 git 历史 + 作者」——**你刚碰过的文件他自动让路**（顺带修 `self_review` 冷却那个真实存在的小 bug）。
3. **重新认识自己**：外部若加了新 connector/工具，`discover_connectors` 启动会捡到，但 ① 能力索引、`SELF_MODEL.md` 镜像等**缓存要跟着失效重建**，否则他嘴上的能力和实际装的对不上。

**定位**：这是自我叙事的另一半——㉕ 原本记「我对自己做了什么」，现在补「**别人对我做了什么**」，合起来才完整，也才敢长期开着自我进化：你随时可能手动介入，他必须能察觉、能让路、能把你的改动纳入自己的历史。碰的 `self_iteration`/`self_review` 是 **PROTECTED**，须人工审——护栏本身的升级本就该你亲自过目。

**㉖ 跨实例共享自我**
上子 agent 后会有多个实例（交互的 + 后台巡检的 + 半夜巩固的），现在各写各的、无共享自我。半夜分身发现「NAS 端口异常」，早上主线程应已知晓。需跨实例共享状态/交接——spawn 抽象（⑦）要顺带解决，否则多实例制造「左手不知右手」的割裂。

**㉗ 资源/成本自觉**
他不知道烧了多少 token/钱、该用重模型还是 `CLAUDE_MODEL_LIGHT`、一个子 agent 值不值得派。现在预算是写死上限（`_MAX_TOOL_ROUNDS`），非他能感知权衡的一维。接子 agent + 主动巡检后，失控的后台巡检能悄悄烧一大笔。从「硬上限」进化成「他看得见的一维」，挂 ⑨。

### 🟢 关系体验（决定「先你一步」是加分还是惹人烦）

**㉘ 关系/状态读数（主动性阈值的旋钮）**
现在只解析「你说了什么」，读不到「你此刻什么状态」（在忙、烦了、连问三遍、深夜还在处理）。同一条主动提醒，你悠闲时贴心、焦头烂额时打扰。⑬ 监督信号已在攒原料，差把它实时化成「当前该多主动」。

**㉙ 数据足迹自觉与遗忘入口**
保险箱/档案/情节/历史越攒越多，但他没有「我攥了你多少数据」的自我认知，也没有「忘掉/清理」的自省入口。你问「你都存了我哪些」「把关于 X 的都删了」，现在给不出干净答案。与 ⑯ episodic 衰减一体两面——**遗忘是你对他可控感的来源**。

## 阶段 3 · 记忆与学习：从「在线声明」到「离线巩固」

> 现在的写入路径根本问题：模型要在**对话进行中**判断「值不值得记」——最差的时机，标准还是硬 prompt 写死的。必然漏记隐性偏好 + 记进噪音。人是「先全进短期，离线时巩固」。`history.py` 已存完整 transcript，原料齐全，缺巩固作业。

### ⑬ 监督信号打标（很小，越早越好）
巩固需要知道「什么算对」。这些信号现在**全被丢掉**：你的纠正（"不是，我说的是…"）、重问同一件事、无视他的建议、打断流程、他主动开口后你的反应。在 controller 加轻量检测打标存下来。**这条通道打通前，「复盘学习」只是模型对着 transcript 自我感觉良好。**

### ⑭ 巩固作业 `core/consolidation.py`（跑在子 agent，依赖 ⑦⑬）
定时触发，复用 `self_review` 骨架：
```
读最近 N 轮对话 → 抽候选事实/偏好/规则
  → 与现有 L1/L2/L3 比对（去重、冲突消解）
  → 过必要性闸（跨会话反复出现才够格升 L1）
  → 写回 + 产出复盘文档（人可审、可回滚）
```
`remember_fact` 不删，降级成「用户明确说记住这个」的快捷通道。

### ⑮ profile 覆写 / 时效 / provenance
现在 `core_memory` 是 append-only、满 40 条拒绝新增——硬伤（事实会过时会矛盾）。每条事实带 `confidence` / `last_confirmed_at` / `evidence`(指向 episode) / `superseded_by`。**巩固的产出不只「新增」，更是「修正」和「合并」。**

### ⑯ episodic 衰减
`episodes` 表现在只增不减。加 access_count + recency 加权，长期没被召回的降权归档。**遗忘不是 bug 是 feature**——没有遗忘，语义召回信噪比随时间单调下降。

### ⑰ L3 程序性记忆 / 学习层（依赖 ⑭⑮）
「取代硬 prompt 里写的东西」要的正是 L3——「怎么做某件事」的经验规则（报告只在明确要求时生成、结尾别问要不要生成、HubSpot session 会掉要先 check、投资建议加免责声明…）。把 system prompt 拆两层：

- **固定内核**（人格 + 安全边界 + 证件保险箱规则）— 永不可学习修改，等同 PROTECTED
- **学习层 L3** — 巩固产出，带 provenance（哪次对话学到）、confidence、可增删改、**按任务上下文按需注入而非全部常驻**

**provenance 是重点**：让「他为什么突然这么做」随时可查可撤。否则学习是黑箱，三个月后你会不敢用。

---

## 横切项（贯穿各阶段）

### ⑱ 执行遥测
controller 分发工具时记一行（tool/耗时/成功失败/错误摘要）。喂给 `self_review`，让反思从「读这两个文件找问题」变成「这周 `hubspot_session_check` 失败 7 次，报错都是 X，去修它」。加**能力缺口日志**：每当他说「我做不到/没这工具/需你手动」落一条 `capability_gap`，定期聚合 → 主动提议造工具。**这两条日志是主动性的物质基础，比放权重要得多。**

### ⑲ 能力回归集（放权的前提）
`evals/` 基本空。每个技能配一条黄金用例，`run_all` 时跑。**没有这层网，扩大权限就是扩大风险面。**

### ⑳ 目标层 `docs/GOALS.md` / `core/intent.py`
写清「贾维斯服务什么业务、本季度重点、什么算做得好」，注入 `self_review` prompt。没有它，「发展方向」只能是代码风格；有了它，他才能说「你的核心场景是潜客情报，但这条链路上我只有 2 个工具且都没失败重试——这是最该补的地方」。

### ㉚ 产物生命周期与统一图书馆（看得见、天天用；建议当第二刀做）

> **病根：产物从来没被当成「一等对象」。** 现状：产物散在至少四处且互不相通——`DATA_DIR/reports/`（有 index，做得最好）、`workspace/{inbox,results,archive,failed}`（目录建了但全空）、`skills/<名>/`（代码与 `__pycache__` 和产物混在一起）、`docs/`+`docs/archive/`（平铺、无命名规范、无状态、看不出谁作废）。共同点：产物一生下来就没身份——不知谁生的、什么状态、活多久、绑哪个工具。「找不到 / 越积越多 / 乱堆 / 删工具后产物成孤儿」全是这个的后果。

**核心：产物登记表（artifact registry）。** 每个产出落盘时记一行 `{id, producer(tool/workflow/skill/report), kind, path, state(trial/kept/expired), ttl, size, human_label}`（复用 `memory.db`，是 reports index 思路的统一版）。一张表接上全部四个症状：

1. **草稿试用 + 放弃清理**：skill 生命周期在 `active`/`draft` 之间补一个 **`trial` 态**（激活后先试用、能真跑、打标）→「就它了」转 `kept`，「放弃」触发清理。每个产物带 `producer=skill:<名>`，放弃工具时一把捞出其名下所有产物，**由你拍板删/留**（不擅自删）。
2. **回收（治越积越多）**：现在零回收。按 producer 设保留策略（trial 产物 TTL 短、到期自动清；正式产物长/不过期）+ 按总量封顶（超 N 个/N MB 最旧先归档）。**与 ㉙ 遗忘入口同源**——「你攒了我多少」查表即得，「把关于 X 的清了」按 producer/标签一扫。
3. **统一图书馆（治本机找不到）**：加一个**面向人的根目录** `DATA_DIR/图书馆/`，按类型分（报告/清单/文档/情报），文件名带日期+人看得懂的标签。登记表存真实路径，图书馆是**给人看的整理视图**（软链/整理副本）。代码照旧从 `DATA_DIR` 读，Finder 打开 `图书馆/` 一目了然——**「产物在哪」与「代码在哪」彻底分开**，这是现在最缺的一刀。
4. **文档血缘（治乱堆）**：`docs/` frontmatter 加 `status: draft|active|superseded|archived` + `supersedes: <旧文档>`（谁替代谁一眼看清，接 ㉕/⑰ provenance 的文档版）+ 命名规范 + 自动生成的 INDEX（`docs/self_review/` 那种时间戳堆给个目录页）。

**框架契合**：登记表=㉙ 数据足迹的存储底座，顺带喂 ㉔ 回执；草稿试用态=② 先查后建闸的下游（先查有没有→造草稿→试用→保留/弃）；文档血缘=㉕/⑰ provenance 的文档版。**碰的文件几乎全是 OPEN**（`core/reports.py`、`connectors/report_tools.py`、`tool_builder.py`、`skill_policy` 附近），`config.py`（加图书馆路径）是 PROTECTED 但改动极小。**无热点，爆炸半径比 effect 那刀还小**，且是天天有感的改善——故建议紧跟第一刀做。

---

## 三、放权的正确维度

**不是放宽 PROTECTED**（那是你唯一的硬护栏，别动），而是扩大**可自动落地的动作种类**。

现在自我迭代只能「改一个已存在的 OPEN 文件」。可安全扩展到：新建 OPEN 目录下文件、新建 connector、新建 recipe、调整自己 prompt 的非安全段落——同样受先红后绿 + gate + 回滚约束，风险不比现在高，施展空间大一个量级。

再加**影子模式**：新能力先只记录不生效，跑一段时间比对结果，你确认后才转正。比一次性放权更契合现有护栏哲学。

---

## 四、组合层（可选但推荐）：介于 tool 和 workflow 之间

现在只有原子工具和预定义工作流两级，中间是空的，所以任何新需求都掉进「造新工具」。加轻量 **recipe**（已有工具的编排 + 参数，纯声明式、无新代码），让他优先用组合而非写代码解决新需求。

---

## 五、建议的落地顺序

**开场两刀（一硬一软，先建手感与信心）**
- **第一刀 = ③ effects 最小闭环**：`effects.py`（五级 + `classify`，纯函数好测）→ `ToolSpec` 加 `effect` 字段并给现有工具标一遍 → controller 分发前加**一个** if（遇 `irreversible` 强制确认）→ 一条 eval。**只碰一个 PROTECTED 文件一小段，却把「运行时护栏」骨架立起，卡住后面所有扩权。**「胶水在里、逻辑在外」压小改动。
- **第二刀 = ㉚ 产物图书馆**：登记表 + `图书馆/` + 草稿试用态。零架构风险、纯增量、天天有感。一硬（看不见但重要）一软（看得见天天用），对这套改造的手感和信心都有了。

**第一周（地基，立刻见效）**
1. ① 能力索引 + ② 先查后建闸 → 当即消掉重复造轮子（②与㉚草稿试用态相接）
2. ③ effects + ④ trust → 后续一切扩张的运行时护栏
3. ⑬ 监督信号打标 → 很小，但越早开始攒数据越好
4. ⑱ 执行遥测 → 同上，给进化提供燃料

**第二周（减负 + 处境感知起手）**
5. ⑦ spawn 抽象 → 把造工具与 self_review 从主线程剥离
6. ⑧⑨ 白名单授权 + 预算
7. ㉒ 渠道感知进 context（改动最小，顺手先做）

**扩权前置（务必在阶段 2 扩权动作之前完成）**
8. ㉓ 自体健康感知 → **放权前置：他得知道自己是死是活**（㉑ 身份核验已删——访问安全由 Ned 自行控制）

**第三～四周（感官）**
9. ⑩ 设备状态感知 → ⑪ 邮箱只读接入（第一档）；期间补 ㉔ 动作回执

**之后（记忆与学习 + 处境感知补全，需前面的燃料管到位）**
10. ⑭ 巩固作业 → ⑮⑯ profile/episodic 改造 → ⑰ L3 学习层
11. ㉕ 自我变更史 / ㉖ 跨实例共享（随 ⑦ 落地）/ ㉗ 资源自觉（随 ⑨）/ ㉘ 关系读数（随 ⑬）/ ㉙ 数据足迹（随 ⑯）

**贯穿**：⑲ 能力回归集随每个新技能补；⑳ 目标层任何时候都可先写。

---

*一句话：差别不在他能做多少事，在于从「我调用他」变成「他在旁边」。能力越长，越要先长出配套的护栏和监督——这份路线图的每一步，都是「先补一层网，再放一段绳」。*
